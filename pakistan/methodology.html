Every figure should be traceable to the publisher's own data, and every step from that data to the page should be repeatable by anyone with the same files.

Two kinds of figure

Official data feed. Downloaded directly from the publisher's own data service, such as the State Bank of Pakistan's EasyData, the World Bank or the IMF, and turned into the figure on the page by code. Each one shows the publisher, the series code, the calculation used, when the data was downloaded, and the fingerprint of the file it came from.

Interim. Read from the publisher's release, or a news report of it, with a link to that source. Figures move from interim to an official feed one at a time, once the feed's values have been checked against the publisher's own release.

News reports are used to describe what happened in a week, never as the source of a figure that an official feed provides.

From the publisher to the page

  1. Download. Each series is requested from the publisher's data service using the series code listed on the Sources page.
  2. Archive. The file is kept exactly as received, with the address it came from, the time it was downloaded and its SHA-256 fingerprint. Archived files are never edited or overwritten.
  3. Store. Values are added to a series history. When a publisher revises a past value, the new value is added and the old one kept, so every earlier version stays available.
  4. Calculate. A named calculation turns the series into the figure, for example the change on a year earlier. Calculations are listed below and are never changed in place.
  5. Check. Every figure passes the checks below before it can be published.
  6. Review. Each weekly update is read and approved before it goes live, starting from a report of what was downloaded, what changed and what every check found.
  7. Publish. The figure appears on the dashboard with its lineage: publisher, series, calculation, download time and file fingerprint.

If an official figure cannot be refreshed, or a new value fails a check, the last checked value stays on the page with its own date until the problem is resolved.

Calculations

Each figure records the calculation that produced it. The number after @ is its version: a change in method gets a new version rather than altering an old one.

as_published@1
The latest value exactly as the publisher released it.
yoy_pct@1
Percentage change on the same period a year earlier: latest value divided by the value twelve months (or four quarters) before, minus one.
mom_pct@1
Percentage change on the previous month.
fytd_sum@1
Sum of monthly values from July, the start of the fiscal year, to the latest month. Every month must be present.
fytd_mean_yoy_pct@1
Average of an index from July to the latest month, compared with the average for the same months a year earlier. This is how average inflation and manufacturing growth so far this fiscal year are reported.
calendar_year@1
The value for the current year in an annual series.
next_calendar_year@1
The value for the following year in an annual series, such as an IMF projection.
recent@1
For charts: the latest months of a series, exactly as published.
fy_months@1
For charts: monthly values as published for this fiscal year so far and the whole of the last one, lined up by month, so a seasonal series is compared like for like.
fy_years@1
For charts: annual values by fiscal year, labelled by the year the fiscal year ends. The current fiscal year is a projection.

Comparisons shown beside a figure, such as last month's reading or the same period a year earlier, use the same calculation on the same stored series.

Some figures combine two official series of the same thing, for example the State Bank's website for the latest treasury bill auction and its EasyData service for earlier ones. Where both cover the same date they must agree; if they do not, the figure is not published.

The arrows beside the headline figures show the latest move against the stated comparison. They are green when the move is better for Pakistan's economy (lower inflation, higher reserves, a smaller external deficit, higher remittances), red when it is worse, and grey for moves that are neither good nor bad in themselves, such as interest rates. The colour is worked out by code from the figures, never set by hand.

Conventions

Pakistan's fiscal year runs from July to June, so FY27 is the year that began in July 2026. Annual figures from international sources are matched to Pakistan's fiscal years, and how each source labels its years is confirmed before its figures are published.

Figures are rounded to the precision the publisher uses. A change worked out from a published index can occasionally differ from the publisher's own rounded figure by one in the last digit; that is one of the things checked before a feed is confirmed.

Derived figures, such as real interest rates, changes since the end of last year and gaps to targets, are worked out from the figures shown on the dashboard, so they move whenever those figures do. The scorecard's statuses and the summaries of forecasters' views are this site's own reading. Nothing here is investment advice.

The archived files behind any official figure can be provided for audit on request through the contact page.
